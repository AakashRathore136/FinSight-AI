# Software Bill of Materials (SBOM) & Build Provenance

This project generates a Software Bill of Materials (SBOM) and signed build
provenance for every push, pull request, and release, via
`.github/workflows/sbom.yml`.

## What gets generated

| Artifact | Format | Purpose |
|---|---|---|
| `sbom.cyclonedx.json` | CycloneDX JSON | Industry-standard SBOM, widely supported by security scanners |
| `sbom.spdx.json` | SPDX JSON | Alternate standard SBOM format, used by many compliance tools |
| Build provenance attestation | in-toto / SLSA | Cryptographically signed record of source commit, workflow run, and builder identity |

## Where to find them

- **SBOM files**: repo → **Actions** → select a `SBOM & Build Provenance` run →
  **Artifacts** section → download `sbom-<commit-sha>`.
- **Provenance attestations**: repo → **Actions** → **Attestations** tab, or via
  the GitHub CLI:
```bash
  gh attestation verify sbom.cyclonedx.json --repo <org>/FinSight-AI
```

## How it's generated

- SBOMs are produced by [Syft](https://github.com/anchore/syft) via
  `anchore/sbom-action`, which scans the repository and auto-detects
  dependency manifests (e.g. `package.json`/lockfiles under `src/`,
  `requirements.txt`/`pyproject.toml` under `api/` if present).
- Provenance is generated by `actions/attest-build-provenance`, which signs
  the SBOM artifacts using Sigstore and publishes the attestation to GitHub's
  attestation store for the repository.

## Verifying an SBOM's provenance

```bash
gh attestation verify sbom.cyclonedx.json --repo <org>/FinSight-AI
gh attestation verify sbom.spdx.json --repo <org>/FinSight-AI
```

A successful verification confirms the file was built by this repository's
GitHub Actions workflow, from the recorded commit, and has not been tampered
with since.

## Future work

This workflow is intentionally decoupled from `ci.yml` and `codeql.yml` so it
can evolve independently — e.g. adding SBOM diffing between releases, or
gating merges on newly introduced vulnerable dependencies.
